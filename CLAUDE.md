# SD-Neo-ModelSwitchRefiner

A Forge / SD WebUI Neo extension. Four areas share one process and, critically, one GPU:

- **Model chain and refiner** — multi-stage image generation, checkpoint switching, Krea 2 and Flux Klein support (`mc_arch.py`, `mc_plan.py`, `scripts/model_chain*.py`)
- **LLM Studio** — local `llama-server` chat with vision, attachments, roles (`mc_llm_*.py`)
- **Voice Chat** — STT and TTS with several selectable engines (`mc_voice_*.py`, `voice/`, `*_worker/`)
- **Voice Box** — VibeVoice 7B on a card of your choosing: samples, prompts, configurations, pipelines, outputs (`mc_voice_box*.py`, `mc_voice_vibevoice*.py`, `vibevoice_worker/`, `mc_turns_guests.py`, `javascript/voice_box.js`)
- **Creative / spatial prompt tooling** — treatments, bounding-box regions, literal prompts (`mc_creative_*.py`, `mc_spatial*.py`, `prompt_master/`)

`README.md` is long and acts as the behavioural specification. Treat it as authoritative for declared behaviour and update it when behaviour changes.

The hard problem running through the whole codebase is **VRAM arbitration**: the image model and the language model want the same card, and most of the subtle bugs in this project's history come from that contention. Since handoff 28 there is a third party to it: Mini Paint NEO's WanGP, on a card of its own, which `mc_wangp.py` gives priority over the language model on that card. Since handoff 31 there is a fourth: a GPU speech guest (VibeVoice 7B, for the Voice Box tab, `docs/23-voice-box.md`) that takes a card only through a turn — `mc_turns.py` decides whose turn it is on each card, holds image jobs at a gate while one is next, parks and brings back the image model, and borrows WanGP's card from Mini Paint through a lease. Since handoff 32 the guest exists: `mc_turns_guests.py` registers it, `mc_voice_vibevoice*.py` and `vibevoice_worker/` are the engine, and `mc_voice_box*.py` with `javascript/voice_box.js` are the tab.

### Shared with Mini Paint NEO — do not rename

The class `forge-assistant-focus-root` (put on the focused panel by `forge_assistant_focus.js`) is read by Mini Paint NEO's `style.css` and `browser/minipaint_wangp.js` to make its WanGP tab the frame alone under focus mode. Renaming it here breaks that silently. The other shared things are older: the dialog layer `--minipaint-dialog-layer: 2000`, the `minipaint:overlay` event, and `visible()`'s reading of a `visibility: hidden` panel as not showing (a parked WanGP panel). And one newer, since handoff 31: **the card lease**, `minipaint_neo.wangp.turns` (`request`/`state`/`flush`/`release`/`report`, a record of exactly `LEASE_KEYS`), which `mc_wangp.lease_*` calls and `mc_turns` drives. Its key set is held closed on both sides (`mc_wangp.LEASE_KEYS` reads a record missing a key as no answer), its `flush` is asynchronous (measure after `held`, never after `flush` returns), and a lease that is `holding` with `bridge_hold: unsupported` is refused rather than waited on. Mini Paint's `docs/wangp/CONTRACTS.md` is its other half.

Since 2026-10-02 there is one more: **`minipaintWanGP.generate()`**, which the flyout's ▶ on the WanGP tab (`tab_wangp`) calls — WanGP's own Generate for the live page, nothing overridden, queued when WanGP is busy. Its name and its answer's `ok`, `status` and `message` are read here; Mini Paint's protocol test holds that it overrides nothing. It stays outside Mini Paint's Clipboard readiness gate on purpose: the user wants ▶ to press WanGP's Generate on whatever model the page is on.

And one in the other direction, read *there*: **the external LLM API, `mc_llm_api`** (`docs/21-external-llm-api.md`), which Mini Paint's `clipboard/enhance.py` imports from this extension's folder. Its MiniMax H3 presses call `submit_minimax`; since 2026-10-03 its LTX 2.3 Distilled presses call `submit_ltx` (`mc_llm_ltx.py`: the first frame only, shown to the model, written into Prompt Studio's history as a *[No settings]* entry) once `capabilities()["kinds"]` lists `"ltx"`, and its enhancement view shows `system_prompt("ltx23", has_image)` as the default it overrides. Since 2026-10-04 its LTX 2.5 Distilled presses call `submit_ltx(..., model="ltx25")` once `capabilities()["ltx_models"]` lists `"ltx25"`: the same writer under the same instructions, one system prompt for both at the user's request, with `model` only naming the prompt (the status line, the console, the Prompt Studio entry's `written_for`); its view edits one LTX set for both, and `system_prompts()["ltx25"]` says `same_as: "ltx23"`. Renaming `submit_ltx` or the `kinds` value makes Mini Paint refuse every LTX press with `ENHANCE_LTX_UNSUPPORTED`; renaming the `ltx23` variant leaves its view with no default to show; renaming `ltx25` or `ltx_models` still writes an LTX 2.5 prompt in the right words but names it LTX 2.3, because Mini Paint asks without `model` when the list does not name it (an unknown model is refused, `unknown_model`).

### Not superseded — a trap in the other direction

**The three TTS engines coexist.** Kokoro (17, 18), Sopro V2 (22) and PocketTTS (23, 24) are all live, selectable backends registered in `mc_voice_engines.py` via the `ENGINES` tuple. Later engines did **not** replace earlier ones. Do not "clean up" Sopro or Kokoro as dead code. LavaSR (24, 26) is the Voice Pipeline's bandwidth-restoration stage (it rebuilds the top of the spectrum a small TTS model cannot generate, after DPDFNet), not a fourth TTS engine. VibeVoice (31, 32) is not a fourth Voice Chat engine either: it is a GPU guest for the Voice Box tab (phase 3, a Voice Chat engine, was built in 33 and rolled back at the user's request — see the superseded table), and every Voice Chat engine stays CPU-only.

### The host's theme rewrites the page — a trap

The user's Forge runs the Lobe theme (`lobehub/sd-webui-lobe-theme`), and it does more than restyle. Its **SVG icon** option, on by default, runs once when its app mounts (and again when its prompt editor does) and replaces the *whole content* of every `<span>` whose text contains `×`, `⤡`, `⊞` or `🖫` with a 36 px icon, and of every `<button>` whose text holds one of its emoji with a 16 px one. A span with a `×` anywhere inside it goes whole: the Voice Box's status actions lost Cancel, Clear queue and Unload that way, leaving one large X beside *Ready* (handoff 36). Never write `×` as text inside a span; draw it. Its stylesheet also draws every native checkbox itself, a fixed square with `flex: 0` and `appearance: none !important`; against the Voice Box's own `min-width: 0` on its field inputs that left Sampling its 2 px border, a sliver that worked when hit and looked like nothing, which is why the Voice Box's settings are drawn switches. And it gives every button `min-width: fit-content !important` (Mini Paint NEO's Clipboard tiles met that one). Its `display` rules are aimed at Gradio's own selectors, but any author rule that sets `display` beats the browser's rule for `[hidden]`, so the Forge Assistant and the Voice Box each carry `[hidden] { display: none !important }`. A check on a plain page proves nothing about any of this; the Voice Box's layout test carries hostile-theme pages, and runs the theme's own icon swap over the built page, for that reason.

## Standing conventions

These recur across the handoffs and the user has restated them repeatedly.

- **Develop on the designated branch.** Commit with clear messages, push when complete. Since handoff 34 the repository's default branch is **`main`** (made at `d34d21d` when 33 was rolled back); the user's WebUI extension folder follows it, and pull requests go into it.
- **Do not open a pull request unless explicitly asked.** The user opens them from the Claude Code UI.
- **No model identifier** in commit messages, PR text, code comments, or anything else pushed to the repository.
- **Run the full suite before every push**: `python3 tools/run_tests.py`, not just the file you touched. It runs every test on every core through pytest-xdist, which `.claude/hooks/session-start.sh` installs in web sessions (about 2½ minutes on four cores, 7¼ on one; `--serial` for file order). Ordering-dependent failures exist: a test passing alone may fail in the suite, or beside another worker. While working, `python3 tools/run_tests.py --affected` runs only the test files the change can reach (`--list` says why): it follows imports, files named in strings, listed folders and the conftest fixtures a test asks for, and cannot see state one test leaves for another, so it never stands in for the full run. `tests/test_vibevoice_upstream.py` skips here: it runs the VibeVoice worker against upstream's own code (a tiny model on the CPU) and needs `torch`, `transformers` 4.51.3, `diffusers` and the `vibevoice` 0.0.1 wheel in a venv; run it with that venv's pytest (about a minute) whenever the worker's solver, attention or per-take randomness changes.
- **A test never writes into the checkout.** The stand-in host's data path is `.`, so a voice or LLM path a test forgot to redirect lands in `model_chain_voice/` or `model_chain_llm/` of the repository, where every later test, run and parallel worker finds it. A guard in `tests/conftest.py` fails such a test: ask for `voice_root`, or point `mc_llm_paths.data_root` at `tmp_path`.
- **Mutation-check new tests.** A test asserting a new invariant must fail when the change is reverted. Several tests in this project's history passed for the wrong reason until checked this way.
- **When a behaviour change invalidates a test's setup** (not its intent), translate the setup rather than deleting the test.
- **Do not edit files while pytest is running** — it invalidates the run.
- **Update `README.md`** when declared behaviour changes.
