Everything under this directory is a copy of that tree with two exclusions, one
addition and one recorded edit:

  * ui/     -- the PySide6 window, chat page, MiniMax page, character editor,
               model chooser and setup wizard. Section 17.B of the design
               intent: the business logic comes across, the Qt presentation
               layer does not. Its Forge replacement is mc_llm_studio.py.
  * app.py  -- the standalone Qt entry point, for the same reason.

The addition is krea/, which is not from that repository at all and never was.
It is the Krea 2 prompt package written for this extension, around a copy of
Krea's own docs/expansion.txt vendored from github.com/krea-ai/krea-2. It
carries its own provenance in krea/UPSTREAM_SOURCE.txt and is the one directory
here that a `diff -r` against LTX_Video_Prompt_Claude will report as extra.

There is now exactly one edit, and it is recorded here rather than left for a
`diff -r` to discover:

  * inference/llama_client.py -- LlamaClient.stream_chat() gained an optional
    `extra_sampling` argument, and the module gained SAMPLING_FIELDS and
    sampling_fields() to filter it. This is the Krea Creativity control (design
    intent §8.2), which needs llama.cpp sampler fields upstream never sends.

    It is an addition and not a rewrite: the parameter defaults to None, the
    filter returns an empty dict for None, and the payload built for every
    existing caller is byte-for-byte the payload built before it existed. The
    whitelist is here rather than in an mc_llm_* wrapper because it is a
    statement about what *this client's* request may contain, and a wrapper
    that filtered on the way in could be bypassed by anything holding the
    client -- which mc_llm_sessions does.

    Re-vendoring means re-applying this one diff. It is small on purpose.

Nothing else was removed and nothing else was rewritten, which is the point.
The prompt engine, its vendored upstream, the MiniMax enhancer, the chat stores
and the provisioning pipeline are all still comparable against their own sources
with `diff -r`, and the parity tooling those trees carry
(prompt_engine/UPSTREAM_COMMIT.txt, minimax/UPSTREAM_SOURCE.txt,
prompt_engine/upstream/README.md) still describes them accurately.

Two consequences of dropping the src/ layer are worth knowing about:

  * core/paths.py::application_dir() looks for app.py three directories up.
    It will not find one here, and it is not meant to -- mc_llm_paths.py
    constructs AppPaths against a Forge-chosen root directly rather than
    letting it discover one. The function is left exactly as upstream wrote
    it so the file still diffs clean.
  * setup_cli.py is kept. It is the console half of the provisioning pipeline,
    it has never needed Qt, and it stays a working fallback for provisioning a
    runtime when the Gradio panel cannot (a headless install, a first run
    before the WebUI starts).

modules that sit on top of them, and anything that genuinely cannot live there
gets a paragraph in this file before it gets a line of code.
