# Krea 2 Creative Mode starter library — where it came from

creativity/ is a byte-for-byte copy of the krea2_creativity_library data package
delivered with the Krea 2 Creative Mode design intent. It is data only: axis
vocabulary, expression tiers, activation and sampling policy, compatibility
rules, anti-repetition policy, worked examples and acceptance cases. There is no
code in it and nothing in it is executed.

# the one edited file

defaults.json as delivered sets nine of the ten axes to Vary. That makes a fresh
install arrive with nine art-direction decisions already taken, none of which the
user made and none of which is visible until they open the drawer and read ten
rows. The fresh state is now every axis Natural, no Fixed values and no
exclusions: Creative Mode influences nothing until somebody adds a direction, and
what it influences is exactly the list of directions they added.

Nothing else in the package moved. The Vary-by-default choice is a *preference*
about how the feature should open, which is what a defaults file is for, and it
is the one file in here that describes this installation rather than the
vocabulary. `excluded_values` is added to it for the same reason the panel has
exclusions at all — see §3 of the Creative Mode rebuild spec — and an absent key
still reads as "no exclusions".

# why it is vendored rather than fetched

The same reason expansion.txt is (see UPSTREAM_SOURCE.txt): a prompt written
here does not depend on a network call. It is also why the package is copied
whole rather than trimmed — examples/ and tests/ are not loaded at run time, but
they are what a later version of the library will be diffed against, and a
vendored package that dropped half its files is a package nobody can update
cleanly.

# what may and may not be edited

The package is independently versioned and is meant to be extended: adding a
variant family, adding an axis entry, or retuning the activation counts is a
data edit, and `library.py` is written so that those need no code change.

Two rules, both from the package's own README:

  * Stable IDs must not be renamed after release. A saved Fixed axis selection
    stores a variant id, so renaming one silently changes what a user's saved
    configuration means.
  * Every entry needs all four expression tiers. `library.py` refuses to load an
    entry that is missing one rather than falling back to a neighbouring tier,
    because a silently substituted tier is a Creativity slider that stops
    scaling on one axis and says nothing about it.

To update: replace creativity/ wholesale from a newer package, record the new
version and digests here, and run the tests — `tests/test_krea_creative.py`
checks the library against its own schema, its own examples and its own
acceptance cases, so a package that has drifted from its promises fails there
rather than in somebody's prompt.

# one number that is deliberately duplicated in code

`creativity_policy.json` carries the Krea writer's sampling table, and
`prompt_master/krea/variation.py` carries the same eleven rows as Python
literals. That is not an oversight and not a cache: Creativity 0 and 1 are
compatibility guarantees, and a library that failed to load must not be able to
change what the writer samples at those positions. A test asserts the two agree,
so the duplication cannot drift — it can only fail loudly.
